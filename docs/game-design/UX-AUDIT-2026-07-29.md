## Cross-cutting issue (appears on every screen)

![Dashboard desktop](dashboard-desktop.png)

**Header title overlap/wrap bug.** "Mark Vinicius Cherry Tycoon" wraps to two lines and the "v3.8" version badge overlaps into the wrapped text, on every single screen (visible identically in all 8 screenshots in this folder). This isn't a one-page bug — it's a layout-system problem in the persistent sidebar header, which means it's a **Phase 9 foundational fix, not a per-screen fix**. Any redesign work should fix the shared layout shell first, or every other screen redesign will inherit the same bug.

## Per-screen findings

### Onboarding modal (desktop)
![Onboarding](onboarding-desktop.png)

Functionally fine and on-brand copy ("Every great empire starts with a single seed"), starter-stats preview is clear. Consistent with the audit finding that this modal is well-built but **auto-bypassed off-mainnet** (`ONBOARD-01`) — confirmed live in this same session (see below).

### Farm Overview / Dashboard (desktop + mobile)
![Dashboard mobile](dashboard-mobile.png)

- The orchard/farm plot view is almost empty — a plain dark rhombus with a single small tractor icon and scattered particle dots. This is the game's signature view and it currently has the least visual density of any screen, the opposite of what the lore promises ("tactile diorama," "God Rays," "Golden Hour warmth").
- Two grey placeholder boxes in the bottom-left sidebar never resolve to content in either screenshot — looks like a loading state that doesn't finish, or dead UI.
- The bottom "Diagnostics" panel mixes three different visual idioms in one row (a circular gauge, vertical bar meters, and plain text stat blocks) with no shared visual grammar between them.
- Mobile layout is functionally usable (buttons are tappable, phase indicator visible) but inherits the header bug and the same sparse orchard view, now even more prominent for lack of anything else on screen.

### Rankings (desktop)
![Rankings](rankings-desktop.png)

The "Your Standing" card added this session (Phase 1) renders correctly ("Unranked — keep growing to enter the ledger"). Column headers ("Industrialist Identity," "Global Prestige," "Lifespan," "Yield (Ruby)") are styled and legible. This is one of the better-executed screens visually — worth using as a **reference point for "good enough" density/style** when redesigning weaker screens, rather than redesigning everything from zero.

### Neighbors / Competitors (desktop)
![Neighbors](neighbors-desktop.png)

**Visually confirms a bug already tracked in code** (`ECON-06`): every AI rival shows `Market Share: NaN%`, and "Market Trend +4.2%" is the same hardcoded fake number found in `CompetitorsPanel.tsx`. This is not a design question — it's a rendering-a-bug problem that will look broken in any redesign until `ECON-06` is fixed. **Sequencing note: fix `ECON-06` before or during any Phase 9 pass on this screen**, not after — otherwise the redesign will faithfully re-skin a NaN.

Also visible: the player's own row is labeled "Agent Test," not the name typed into the onboarding form ("UX Auditor" was submitted this session) — **live confirmation of `ONBOARD-01`** (the off-mainnet auto-bypass silently created a farm under a hardcoded identity before the submitted form could take effect).

### Sports Center (desktop)
![Sports](sports-desktop.png)

Confirms the "wired stub" finding from the gameplay audit: "Your Sponsorships" and "Available Investments" sections are both fully styled and both completely empty, because the backend hardcodes an empty club list. This screen will look identical after a visual redesign until Phase 2 (Football Clubs) ships real data — **sequencing note: Phase 2 should land before spending redesign effort here**, or the redesign has nothing real to display.

### Marketplace (desktop)
![Marketplace](marketplace-desktop.png)

The best-constructed screen in this audit: a real price-trend line chart (Retail vs. Wholesale across 6 seasons), four asset cards with cost/upkeep/risk tags. **New finding, not previously caught**: one of the four cards is "Processing Plant" ("Enable on-site sorting and cleaning," 100,000 PLN cost) — this looks like a partial, previously-unnoticed implementation of V1's §1.1.4 "Processing (later game phase)" concept, which GDD v3 currently lists under `SIM-04` ("Future / Not Now"). **This needs reconciling**: either this card is decorative/non-functional and should be flagged as another dead lever, or there's a real partial processing-facility implementation that changes the `SIM-04` deferral decision. Not resolved in this audit — flagged for the next code-dig, not guessed at here.

### Imperial Pool / Auctions (desktop)
![Pool](pool-desktop.png)

Also strong: three distinct, colorfully-styled AI rival cards (Marek "The Traditionalist," Kasia "The Eco-Visionary," Hans "The Aggressor" — this is the actual live in-UI naming, useful data point for the `ECON-07` naming-canonicalization decision, since it's a third variant beyond what docs and code internals use), a live Flood Factor indicator, and a spot-price index. ## What this means for Phase 9 scoping

1. **Fix the shared header/layout bug first.** It's cross-cutting; redesigning individual screens before fixing it means redoing that work later.
2. **Two screens (Rankings, Imperial Pool) are already close to the target quality bar** — the redesign doesn't need to invent a new visual language from scratch, it can extend what's already working there to the weaker screens (Dashboard/orchard view, Sports Center once Phase 2 lands, Neighbors once `ECON-06` lands).
3. **Sequencing matters**: don't spend redesign effort on Sports Center before Phase 2 ships real club data, and fix `ECON-06`/`ONBOARD-01` before or during (not after) any redesign touching Neighbors/onboarding — otherwise real bugs get faithfully re-skinned instead of fixed.
4. **One open question, not yet resolved**: the "Processing Plant" marketplace card vs. the `SIM-04` deferral decision — needs a quick code check before Phase 9 planning finalizes scope.
5. **The orchard/dashboard view is the single biggest visual gap** relative to the lore promise — if Phase 9 has to prioritize one screen, this audit points here first.

## Proposed requirement IDs (replacing the `UX-01` placeholder in `.planning/REQUIREMENTS.md`)

- **UX-01**: Fix the shared sidebar header layout bug (title wrap + version badge overlap) — cross-cutting, affects every screen
- **UX-02**: Redesign the orchard/farm dashboard view to match the "tactile diorama" lore promise (visual density, God Rays/Golden Hour lighting cues)
- **UX-03**: Establish one consistent visual idiom for stat/diagnostic displays (currently mixes circular gauges, bar meters, and plain text blocks with no shared grammar)
- **UX-04**: Resolve the two never-resolving placeholder boxes in the dashboard sidebar
- **UX-05**: Reconcile the "Processing Plant" marketplace card against the `SIM-04` deferral decision (functional partial-implementation vs. decorative dead lever)

These are proposals for the next Discuss/Plan pass on Phase 9, not yet committed to the roadmap — intentionally left for review before locking in.
