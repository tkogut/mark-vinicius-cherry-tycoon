# Mark Vinicius Cherry Tycoon

Cherry-farming tycoon sim on the Internet Computer (ICP). Motoko backend (dual entrypoint) + React/Vite/TS frontend.

This file is routing and hard rules only. Long-form context lives in `.planning/` (GSD Core) and `docs/`.

> **Instruction budget:** keep this file under ~16 KB. It is read in full every session, so anything that is not a rule or a route belongs in the file it would point at. Currently ~9 KB.

## Always

- Read `.planning/STATE.md` at the start of every session — it is where we actually are.
- Check the **Task Router** below before researching or coding. One task often matches several rows; read all of them.
- Read `.planning/LESSONS.md` before working in a subsystem it names. It is mistakes that already happened here, written as rules.
- When you change `backend/game_logic.mo`, change `frontend/src/lib/gameLogic.ts` **in the same commit**, and extend `economyParity.test.ts`. The mirror is load-bearing: the UI quotes these numbers to the player.
- Verify backend behaviour on a live replica, not by compiling. Put the observed values in the commit message.
- Prove a new guard or test works by breaking the thing it guards and watching it fail.
- Report what actually happened, including the parts that did not work. A skipped gate is stated, not omitted.
- After a correction from the user — or from a gate catching something you believed was fine — add an entry to `.planning/LESSONS.md` the same session.

## Ask First

- **Economy balance numbers**: prices, yields, upkeep percentages, repair costs, difficulty constants. Present options, don't apply a recommendation silently. (This rule exists because MAINT-02's repair coefficient was decided unilaterally one step after asking about MAINT-01's.)
- Changing the **Candid interface** — removing or renaming a public canister method, or changing an argument/result shape. Additive is usually fine; anything else breaks deployed frontends. See Contract surfaces.
- Changing the shape of **stable state** (`stable var`, the `Farm` record, `Infrastructure`). On ICP a bad upgrade loses player data irreversibly.
- Touching `.github/workflows/**`, `dfx.json`, or anything in the deploy path.
- Adding a production dependency, to either side.
- Reducing the scope of what was asked for. Deliver the whole thing under stated assumptions instead, and say what is uncertain.

## Never

- Never commit or read into context: secrets, credentials, tokens, private keys, or PII. `.env`, `.env.*`, `.secrets` are hook-denied (`.claude/settings.local.json`). `DFX_IDENTITY_PEM` exists only as a GitHub Actions secret.
- Never copy actor declarations or persistence keywords (`stable var` vs `persistent actor`/`transient`) between `backend/main.mo` and `backend/main_mainnet.mo`. They are architecturally separate — `docs/game-design/backend/track-separation.md`.
- Never mirror a Track A change into Track B without checking whether it is *meaningful* there. Track B does not compile (EOP-01), so edits are unverifiable; and some changes are actively wrong there (MAINT-02's wear-based repair pricing would make repair a permanent free no-op in a track that has no wear).
- Never raise the lint warning ceiling to make `npm run lint` pass. It only goes down (183 today, from 185). Errors stay at 0.
- Never edit `frontend/src/declarations/**` by hand — it is generated by `dfx generate` and committed as a drift guard.
- Never paper over a known defect you happen to touch. Flag it, and add it to `.planning/REQUIREMENTS.md` if it is not there.
- Never report "tests pass" as evidence that behaviour is correct. See `.planning/LESSONS.md` → Verification.

## Validation

```bash
./validate.sh fast      # unit + lint + typecheck              (~15s)
./validate.sh full      # + build + e2e + declaration drift    (~60s)
./validate.sh backend   # moc type-check of both Motoko tracks
```

Pick the smallest tier that covers the change and **say which tier you ran**. `fast` for frontend logic; `full` for anything rendering (`.tsx`) and before any commit; `backend` plus a live replica check for `backend/*.mo`.

Neither tier starts a replica. Backend behaviour is proven by `dfx deploy backend` and reading values back — nothing else.

## Dual entrypoint — hard constraint

`backend/main.mo` is Track A (local / dfx / Playground). `backend/main_mainnet.mo` is Track B (mainnet). They are separate on purpose; see the `Never` rules above and `docs/game-design/backend/track-separation.md`.

**Current state of Track B, verified 2026-08-07:** it does not compile (`duplicate field name activeInsurance` at line 261, plus contract type errors around 1591) and nothing builds it — `deploy-mainnet.yml:43` deploys a canister named `backend_mainnet` which **is not in `dfx.json`**. So the mainnet path is dead twice over, and has been unnoticed because that workflow is manual `workflow_dispatch` and has never run. Tracked under `EOP-01`; not fixed pending a decision on whether mainnet matters yet.

```bash
# Frontend (from frontend/)

npm run build          # tsc && vite build

npm run typecheck

bash execution/tests/e2e_backend.sh 2>&1 | tee .tmp/backend.log
```

`execution/tests/*.sh` (23 scripts) are the historical backend suite against a live replica. 11 are healthy and 12 are broken/stale — the split is snapshotted in `legacyShellScripts.test.ts` and porting them is `QUAL-09`.
