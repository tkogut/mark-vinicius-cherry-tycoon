# Architecture — Mark Vinicius Cherry Tycoon

Analysis date: 2026-07-29
Scope: `backend/` (Motoko/ICP canister) + `frontend/src/` (Vite/React/TS)

## 1. System Overview

The game is a single-canister ICP dApp. The frontend is a static-asset canister (built by Vite) that
talks to a Motoko backend canister over the Candid interface via `@dfinity/agent`. Auth is Internet
Identity (`@dfinity/auth-client`). There is no separate REST/API server — "the API" *is* the Candid
service exposed by the Motoko actor.

## 2. Component Responsibilities

## 3. Dual-Entrypoint Pattern (Track A / Track B) — Architectural Constraint

This is the single most important structural rule in the backend, documented in
`docs/game-design/backend/track-separation.md` and `docs/game-design/backend/dual-entrypoint-sync-rules.md`:

- **Track A — `backend/main.mo`**: local replica + ICP Playground. Built with `dfx 0.24.3`. Uses the
  classic Motoko paradigm: `actor CherryTycoon { ... stable var ... }`, manual `system func preupgrade`/
  `postupgrade` serialization into `stable var stableX : [...]` arrays (see lines 83-117 of `main.mo`).
  This is the canister referenced by `dfx.json`'s `"backend"` target and is what
  `frontend/src/declarations/` is generated from in local dev.
- **Track B — `backend/main_mainnet.mo`**: intended for mainnet with Enhanced Orthogonal Persistence.
  The file header comment says "Uses Enhanced Orthogonal Persistence (persistent actor)" and
  `docs/game-design/backend/track-separation.md` mandates it use `persistent actor` + `transient` state.
  **Drift note (as of 2026-07-29): the actual code still declares `actor CherryTycoon { ... stable var ... }`**,
  i.e. it has not yet been migrated to the EOP syntax the docs prescribe — treat this as an open
  architectural TODO, not a contradiction to "fix" by copying Track A wholesale.
- **Isolation rule**: NEVER share actor declarations, `stable`/`persistent`/`transient` keyword usage,
  or `preupgrade`/`postupgrade` bodies between the two files. Each track is compiled and deployed with a
  different dfx/Motoko version (`0.24.3` vs `>= 0.30.2`) and the persistence models are not interchangeable.
- **1:1 logic parity rule**: every gameplay logic change made in one entrypoint's public functions MUST
  be mirrored in the other. Both files import the *same* shared logic modules (`game_logic.mo`,
  `auction_logic.mo`, etc.), so most business logic changes only need to happen once in the shared module
  — but any change to the actor-level orchestration (new public function, new stable field, changed
  preupgrade/postupgrade wiring) must be applied to both `main.mo` and `main_mainnet.mo` by hand.
  `docs/game-design/backend/dual-entrypoint-sync-rules.md` explicitly calls out "Math Drift" between the
  two tracks as a known historical failure mode.
- Deployment mapping: `.github/workflows/deploy-playground.yml` deploys the `backend` canister
  (`main.mo`) to the `playground` network on every push to `master`; `.github/workflows/deploy-mainnet.yml`
  is a manual `workflow_dispatch` gated by a typed `"deploy"` confirmation that deploys `backend_mainnet`
  (`main_mainnet.mo`) to `--network ic`.

## 4. Data Flow — Example: Submitting an Auction Bid

1. User clicks "Submit Bid" in `frontend/src/components/pools/BidModal.tsx` (rendered from
   `AuctionDashboard.tsx`, active when `App.tsx`'s `activeTab === 'pool'`).
2. The modal calls `submitBid.mutate({ contractId, offerPrice })`, where `submitBid` comes from
   `frontend/src/hooks/useAuction.ts`.
3. `useAuction.ts`'s `submitBidMutation` reads `backendActor` from `useAuth()` (i.e. from
   `AuthContext`), guards `if (!backendActor) throw new Error('Not authenticated')`, then calls
   `backendActor.submitAuctionBid(contractId, BigInt(offerPrice))`.
4. `backendActor` is a Candid proxy created by `frontend/src/api/actor.ts::createBackendActor`; the
   call is encoded via `idlFactory` from `frontend/src/declarations/backend.did.js` and sent over
   `HttpAgent` to the canister (canister ID resolved per network — local/playground/mainnet).
5. On the canister, this hits `public shared({ caller }) func submitAuctionBid(contractId, offerPricePLN)`
   in `backend/main.mo` (line ~3067) — or the mirrored function in `main_mainnet.mo` for the mainnet
   deployment. It:
   - rejects anonymous callers (`Principal.isAnonymous(caller)`) → `#Err(#Unauthorized(...))`,
   - looks up the caller's farm in `playerFarms` → `#Err(#NotFound(...))` if missing,
   - enforces the season-phase gate (`farm.currentPhase != #Market`) → `#Err(#SeasonalRestriction(...))`,
   - locates the contract in `stableAuctionContracts`, delegates bid validation/insertion to
     `backend/auction_logic.mo`,
   - returns `GameResult<Text, GameError>` (i.e. `#Ok(Text) | #Err(GameError)`).
6. The response comes back through the agent, `useAuction.ts` unwraps `'Err' in result` (throwing a
   mapped message via `getErrorMessage`) or returns `result.Ok`.
7. `onSuccess`: React Query invalidates `ACTIVE_CONTRACTS_QUERY_KEY`, a toast fires, and
   `playSFX(SOUNDS.GAME.CASH)` plays via `AudioContext`. `onError`: a destructive toast shows the
   mapped `GameError` message.
8. The invalidated query key triggers `activeContractsQuery` in `useAuction.ts` to refetch
   `getActiveContracts()`, re-rendering `AuctionDashboard`/`AuctionContractCard` with fresh data.

The same shape applies to farm actions (`plant`, `water`, `harvest`, etc. in `App.tsx`'s
`handleParcelAction`, backed by `frontend/src/hooks/useFarm.ts`): UI event → hook mutation → guarded
`backendActor` call → Candid encode → canister `public shared` function → phase/ownership checks →
delegate to a `*_logic.mo` module → `GameResult<T, GameError>` → hook unwraps/toasts → React Query
cache invalidation (`FARM_QUERY_KEY`) → re-render.

## 5. Key Abstractions

- **Candid actor interface (`_SERVICE`)**: the single contract boundary between frontend and backend,
  defined by `frontend/src/declarations/backend.did` (source of truth is whatever `.mo` file `dfx build`
  compiled — locally that's `backend/main.mo`). All hooks type their `backendActor` as `_SERVICE`.
- **`GameResult<T, GameError>`** (`backend/types.mo`): every mutating/query game function returns
  `#Ok(T) | #Err(GameError)` rather than trapping, so the frontend can render structured error UI. See
  §6 for the full `GameError` variant list.
- **React Query (`@tanstack/react-query`)**: wraps every backend call as a `useQuery`/`useMutation`.
  Query keys (`FARM_QUERY_KEY`, `MARKET_STATE_QUERY_KEY`, `ACTIVE_CONTRACTS_QUERY_KEY`) are exported
  constants used both for the query itself and for `invalidateQueries` after related mutations —
  this is the app's cache-consistency mechanism (no websockets/polling push from the canister).
- **`AuthContext`** (`frontend/src/context/AuthContext.tsx`): the sole owner of `backendActor` /
  `identity` / `isAuthenticated`. **Documented invariant: `isAuthenticated` must only be set to `true`
  after `backendActor` is already set** — see the comment `// ONLY set isAuthenticated after we have
  the actor` at line 107, and the mirrored ordering in the initial-load effect (lines 40-45) and
  `initTestMode` (lines 148-169, which sets `isAuthenticated` optimistically then reverts on failure —
  this is the one intentional exception, guarded by a try/catch and explicit revert). Any new code path
  that creates a session (SSO variant, test mode, etc.) must preserve this ordering, because every hook
  gates its query/mutation on `!!backendActor && isAuthenticated` (see `useFarm.ts`, `useAuction.ts`).
- **Phase gating mirrored client/server**: `frontend/src/config/phaseConstants.ts` (`isActionAllowed`,
  `SeasonPhase`, `GameAction`) mirrors the phase checks the canister enforces authoritatively (e.g.
  `farm.currentPhase != #Market` in `submitAuctionBid`). The client-side check is UX-only (fast
  feedback/toast); the canister check is the actual security/consistency boundary.
- **Logic modules as pure(ish) libraries**: `game_logic.mo`, `auction_logic.mo`, `market_logic.mo`, etc.
  are imported by both actor entrypoints and generally operate on explicit state/parameters passed in
  by the actor, keeping the two `main*.mo` files thin orchestration layers over shared business logic.

## 6. Entry Points

- Backend build entry: `backend/main.mo` (declared as the `backend` canister's `main` in `dfx.json`);
  `backend/main_mainnet.mo` is the mainnet counterpart, deployed as `backend_mainnet` (see
  `.github/workflows/deploy-mainnet.yml`; not present as a canister target in the checked-in `dfx.json`,
  which only declares `backend`/`frontend`/`internet_identity` — the mainnet canister id/target is
  managed via CI env vars, not `dfx.json`).
- Frontend build/runtime entry: `frontend/src/main.tsx` → `frontend/src/App.tsx`.
- Frontend static-asset canister: `dfx.json`'s `"frontend"` canister serves `frontend/dist` (Vite build
  output) and depends on `backend`.
- CI entry points: `.github/workflows/deploy-playground.yml` (auto, on push to `master`),
  `.github/workflows/deploy-mainnet.yml` (manual, confirmation-gated).

## 7. Error Handling Approach

- **Backend**: no `Debug.trap`/exceptions for expected failure modes. Every public game function
  returns `Types.Result<T, E>` (`GameResult<T, GameError>`). `GameError` (`backend/types.mo` lines
  423-431) is a closed variant: `#NotFound`, `#Unauthorized`, `#InsufficientFunds { required; available }`,
  `#BankruptcyRisk { estimatedCostUntilHarvest; available }`, `#InvalidOperation`, `#SeasonalRestriction`,
  `#AlreadyExists`. Anonymous-caller checks (`Principal.isAnonymous(caller)`) and phase/ownership checks
  happen at the top of each actor function before delegating to logic modules.
- **Frontend**: each hook defines a local `getErrorMessage(error: GameError): string` that pattern-matches
  the variant and produces a user-facing string (see `useFarm.ts` and `useAuction.ts`, which both
  duplicate this mapping — a candidate for extraction into a shared `lib/` helper if a third hook needs
  it). React Query's `onError` feeds this into `useToast()` for destructive toasts; `mutation.isPending`
  drives disabled/loading UI states.
- Unhandled/transport-level errors (network failure, actor creation failure) surface as thrown `Error`s
  caught by the same `onError` handlers or by the top-level `isError`/`farmError` branch in `App.tsx`
  (the "System Malfunction" panel).

## 8. Cross-Cutting Concerns

- **Auth**: Internet Identity via `@dfinity/auth-client`, centralized in `AuthContext.tsx`. Local/
  playground builds get an **auto-login bypass** (`network !== 'ic'` branch generates an ephemeral
  `Ed25519KeyIdentity` so agents/testers skip the II flow) and a dev-only `initTestMode()` escape hatch
  guarded against `VITE_DFX_NETWORK === 'ic'`. Any change to this flow must preserve the
  isAuthenticated-after-backendActor invariant from §5.
- **Authorization (RBAC)**: `backend/authorization/access-control.mo` + `MixinAuthorization.mo` implement
  admin/user roles (`getCallerUserRole`, `assignCallerUserRole`, `isCallerAdmin`,
  `_initializeAccessControlWithSecret`). Both entrypoints wire this identically near the top of the actor
  body — keep this block byte-for-byte identical between `main.mo` and `main_mainnet.mo` when touching it.
- **Logging**: backend uses `Debug.print`/`debug_show` sparingly for error message interpolation (no
  structured logging/telemetry canister). Frontend uses `console.log`/`console.error` with a
  `[ComponentName]`-prefixed convention (heavily used in `AuthContext.tsx` and `useFarm.ts`) — useful
  for tracing auth/query lifecycle in browser devtools but not aggregated anywhere; treat as dev-only
  breadcrumbs, not production observability.
- **i18n**: `frontend/src/i18n.ts` + `frontend/src/locales/` via `react-i18next`, provider mounted in
  `App.tsx`'s default export wrapping `AppContent`.
- **Audio**: `frontend/src/contexts/AudioContext.tsx` + `frontend/src/config/sounds.ts`, independent
  cross-cutting concern consumed by both gameplay hooks (SFX on mutation success/failure) and `App.tsx`
  (BGM keyed to season).
- **PWA**: `frontend/src/utils/pwa.ts`, service worker registration in `main.tsx`, install-prompt UX in
  `App.tsx`'s `InstallPrompt`.
