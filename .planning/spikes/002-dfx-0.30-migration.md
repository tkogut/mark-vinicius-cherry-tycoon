# Spike 002: dfx 0.24.3 -> 0.30.2 (moc 0.13.4 -> 0.16.3), Track A

Date: 2026-11-21. Branch `spike/dfx-0.30`, **not for merge**. Local replica only, `DFX_TELEMETRY=off`
(telemetry is on by default since dfx 0.26.0).

## What the spike changed (on the branch)

- `backend/main.mo`: `actor` -> `persistent actor`; the nine declarations reported as M0219 got the `transient`
  keyword (`accessControlState`, `globalSeasonNumber`, `baseRetailPrice`, `baseWholesalePrice`,
  `topPlayersCache`, `regionalMarketSaturation`, `aiCompetitors`, `playerFarms`, `LEADERBOARD_MAX_PLAYERS`).
  They were already implicitly transient, and `postupgrade` restores them from the `stable var` copies, so
  semantics are unchanged.
- `dfx.json`: `"args": "--enhanced-orthogonal-persistence"` on `backend` (see finding 2).
- `frontend/src/declarations/*`: regenerated by `dfx generate` under 0.30.2.

## Findings

1. **No source is compatible with both toolchains.** moc 0.13.4 (dfx 0.24.3) rejects `transient`
   (`syntax error [M0001]` at the first one); moc 0.16.3 rejects the classic `actor` (M0220: "should be
   declared `persistent`") and the nine undeclared members (M0219). The migration is one switch for the whole
   repo, and `deploy-playground.yml` / `test-backend-logic.yml` pin 0.24.3 while `deploy-mainnet.yml` already
   pins 0.30.2.
2. **Upgrade needs an explicit, irreversible opt-in.** Upgrading an installed classic-persistence canister with
   the new build, without the flag, traps in `post_upgrade`: "Detected implicit upgrade from classical
   orthogonal persistence to enhanced orthogonal persistence. Recompile with explicit flag
   --enhanced-orthogonal-persistence and redeploy to enable this irreversible migration." The failed upgrade
   left the old canister running (state intact). Putting that flag in `dfx.json` is Ask First (deploy path,
   stable memory layout).
3. **With the flag, the upgrade preserved state.** Old wasm (built by dfx 0.24.3 from `master`) installed on a
   0.30.2 replica, player `AgentTest` taken Hiring -> Investment -> Warehouse bought -> one more phase.
   `getPlayerFarm` (3,510 bytes) and `getAvailableFootballClubs` were byte-identical before and after the
   upgrade; play continued (`advancePhase` Ok). A second upgrade with identical code (EOP -> EOP) was also
   byte-identical.
4. **Public interface:** the 54 method names in the regenerated `backend.did` equal the committed ones.
   The file differs (50 insertions, 220 deletions) by type-alias de-duplication (`Province__1` etc.). Argument
   and result shapes were **not** diffed method by method, and `candidContract.test.ts` was not run on this
   branch.
5. `validate.sh backend` with the corrected base-dir lookup (PR #25) is what lets Track A be type-checked under
   the active dfx.

- Races: nothing here retests the concurrency fix (PR #23).
