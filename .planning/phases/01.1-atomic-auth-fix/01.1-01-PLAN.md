# Plan 01.1-01: Atomic Auth Fix (INSERTED)

**Phase:** 1.1 — Atomic Auth Fix
**Requirements:** AUTH-01

## Discuss

Confirmed during Phase 1 codebase mapping: `frontend/src/context/AuthContext.tsx:150` (`initTestMode()`) called `setIsAuthenticated(true)` immediately, before generating a session identity or creating a `backendActor` — comment said "Set authenticated immediately to provide UI feedback." This violates the Atomic Auth invariant (`isAuthenticated` must be set only after `backendActor` is ready), documented in `.planning/PROJECT.md` and `.planning/ROADMAP.md`, and already correctly followed in `login()` (`setBackendActor(actor); setIsAuthenticated(true);` in that order).

Risk of the bug: any UI gated on `isAuthenticated` (rather than `!!backendActor`) could render and attempt backend calls through a `backendActor` that is still `null`, during the async gap between the two state updates.

## Plan

1. In `initTestMode()`, remove the early `setIsAuthenticated(true)`.
2. Move `setIsAuthenticated(true)` to after `setBackendActor(actor)`, inside the existing `if (actor)` guard — same ordering `login()` already uses.
3. No other code path touched (`login()`, `logout()`, the main `useEffect` init flow were already correct per Phase 1 mapping).

## Success Criteria

1. `isAuthenticated` is only ever `true` after `backendActor` is non-null, in every code path including `initTestMode()`.
2. `npm run build` still passes.
3. No behavior change to `login()`/`logout()`/main init flow (untouched).

## Verify

- `npm run build`: clean.
- `useAuth.test.tsx`: does not exercise `initTestMode()` at all (only covers `login`/`logout`/init flow), and independently fails 5/6 tests for an unrelated, pre-existing reason (missing `QueryClientProvider` wrapper — see `.planning/codebase/CONCERNS.md`). Adding a regression test for `initTestMode()` specifically would require fixing that wrapper issue first — tracked under Phase 3 (`QUAL-01`), intentionally not bundled into this fix to keep it a single, reviewable change.

## Out of Scope for this plan

- Fixing `useAuth.test.tsx`'s `QueryClientProvider` issue (Phase 3).
- Any other AuthContext behavior (auto-login bypass for non-`ic` networks, hardcoded fallback canister ID noted during Phase 1 codebase mapping) — not part of this invariant fix.
