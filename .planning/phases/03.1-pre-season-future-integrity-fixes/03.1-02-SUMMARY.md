# Phase 3.1 Plan 02: ECON-09 Commitment Fee Integrity Summary (final plan of Phase 3.1)

**Closed the free-lock-in exploit in `commitPreSeasonFuture` by validating `volumeKg` against `contract.requiredVolumeKg` before any fee or state write, with the Candid signature and legitimate caller path left byte-identical, verified before/after on a live dfx replica.**

This is the **final plan of Phase 3.1 (Pre-Season Future Integrity Fixes)** — both ECON-08 (plan 03.1-01) and ECON-09 (this plan) are now closed, completing the phase.

## Accomplishments

- Fixed CR-02 (ECON-09): `commitPreSeasonFuture` now rejects any `volumeKg` that does not exactly equal `contract.requiredVolumeKg`, before `calcLockedPrice`, `calcCommitmentFee`, the cash check, or either write. The fee's second argument is now `contract.requiredVolumeKg` rather than the caller-supplied `volumeKg`, so the fee cannot be re-exposed to caller control even if the guard is later loosened.
- Verified live: pre-fix, `commitPreSeasonFuture(psf_S5_0, 1)` against a 10,000 kg Export PSF returned `Ok` with a fee of 0 PLN and flipped the contract to `#Awarded` — the exploit, observed. Post-fix, the same four cases behaved exactly as specified: `volumeKg=1` and `volumeKg=20000` rejected naming the required 10,000 kg, `volumeKg=0` still rejected by the pre-existing zero guard with its original message, and `volumeKg=10000` still succeeds with a fee of 5,000 PLN, cash down by exactly 5,000, `lockedPricePLN=5`.
- Proved the Candid interface did not move a byte: `dfx generate backend` followed by `git status --porcelain frontend/src/declarations/` was empty, and `candidContract.test.ts` (36/36) plus a new arity pin in `preSeasonFutureIntegrity.test.ts` both pass.
- Extended `preSeasonFutureIntegrity.test.ts` with 14 new ECON-09 behavior tests (fee arithmetic transcription, guard ordering, equality-not-lower-bound, Nat-safety backstop) plus 2 new source/interface drift guards, and proved all three protections actually catch their target defect by breaking each in turn and observing the expected isolated failure.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected the exploit's stated locked-price range from "5..17 PLN/kg" to the mathematically accurate range**

- **Found during:** Task 2, while transcribing the exploit arithmetic into a test.
- **Issue:** Both the plan text and `03-REVIEW.md` CR-02 claim the `volumeKg=1` fee "truncates to 0 for every realistic lockedPrice (5-17 PLN/kg)". Checking the actual integer-division arithmetic (`fee = floor(lockedPricePLN * 1 * 10 / 100) = floor(lockedPricePLN / 10)`) shows this is false for `lockedPricePLN >= 10`: at `lockedPricePLN=10` the fee is `1`, not `0`. A test written to assert `0` across the full stated `5..17` range would have failed on `10..17` — not because the exploit isn't real, but because the stated bound was never checked against the arithmetic.
- **Fix:** Replaced the single `5..17` loop test with two accurate tests: (a) the three locked prices the game's PSF categories can actually produce (Export 5, Bio 8, Industrial 2 — all derived from the fixed base prices 6/9/3, since `basePricePLN` is never caller-controlled), confirming the real exploit is unaffected by the review's imprecision; (b) the true `0..9` zero-truncation window plus an explicit assertion that `lockedPricePLN=10` breaks the pattern (fee becomes `1`), documenting the actual boundary instead of a wrong one.
- **Files modified:** `frontend/src/__tests__/preSeasonFutureIntegrity.test.ts`
- **Verification:** Ran the corrected tests — all pass; the original `5..17` version was run first and failed at `lockedPricePLN=10` as predicted, confirming the correction was necessary and not a mistranscription on my part.
- **Committed in:** `8a4e7f2` (Task 2 commit)

## Break-the-Guard Observations (Task 2, all restored before the commit)

1. **Ref guard helper loosened** — Changed `refCommitPreSeasonFuture`'s `if (volumeKg !== requiredVolumeKg)` to `if (false)` (accepting any non-zero volume). Result: 5 tests failed — the four `it.each(1, 9_999, 10_001, 20_000)` mismatch cases plus the explicit over-commitment test — all with `expected 'ok' to be 'mismatch'`. The legitimate `volumeKg=10,000` test and all fee-arithmetic tests stayed green, confirming the loosened helper only breaks the rejection cases, not the happy path.
2. **Motoko guard removed** — Deleted the `if (volumeKg != contract.requiredVolumeKg) { return #Err(#InvalidOperation(...)) }` block from `backend/main.mo`'s `commitPreSeasonFuture`, leaving a `// TEMP` marker. Result: the new source drift guard test (`commitPreSeasonFuture contains a volumeKg != contract.requiredVolumeKg guard ...`) failed with `expected -1 to be greater than -1`, correctly reporting the guard pattern was not found. The separate `calcCommitmentFee(lockedPrice, contract.requiredVolumeKg)` assertion in the same test stayed passing internally (the fee-sourcing half of the code was untouched), isolating exactly which half of the fix regressed.
3. **`.did` arity expectation broken** — Copied `frontend/src/declarations/backend.did`, changed `commitPreSeasonFuture: (text, nat) -> (GameResult);` to `commitPreSeasonFuture: (text) -> (GameResult);`, ran the suite against the edited file. Result: the arity pin test failed with a clear diff — `Expected: ["text", "nat"], Received: ["text"]` — exactly the failure mode an accidental parameter removal during a future refactor would trigger.

All three files were restored to their pre-proof state (`git status --porcelain` confirmed clean on `backend/main.mo` and `frontend/src/declarations/` before the final test run), and the full suite (30/30) was re-run green before committing.
