# Plan 01-01: Enhanced Leaderboard & Rankings UI

**Phase:** 1 — Enhanced Leaderboard & Rankings UI
**Requirements:** LEAD-01, LEAD-02, LEAD-03

## Discuss (findings that changed scope)

The pre-migration roadmap (`.agents/specs/ANTIGRAVITY.md`, since removed) claimed this phase's frontend was entirely missing. Codebase mapping (`.planning/codebase/CONCERNS.md`) flagged this claim as unverified. Direct inspection found it's **wrong**:

- `frontend/src/components/social/RankingsPanel.tsx` already exists, is fully wired to `useLeaderboard()` (`frontend/src/hooks/useFarm.ts:534`, calling `backendActor.getGlobalLeaderboard()`), and is mounted in `frontend/src/App.tsx` behind `activeTab === 'rankings'`.
- It already satisfies most of **LEAD-01** (ranked list) and **LEAD-02** (highlights the current player's row via `entry.isPlayer` → "LOCAL HEGEMON" badge).

Real gaps found by reading the component:

1. **LEAD-02 incomplete**: the player-highlight only works if the player appears in the returned `topPlayersCache` (capped, see `backend/main.mo` SEC-021 guard at 500 players). The backend already exposes `getPlayerRank(playerId: Principal) : async ?Nat` (`backend/main.mo:2901`, candid-bound) specifically for the case where the player isn't in the visible cache — nothing in the frontend calls it. Requirement isn't done until this is used.
2. **LEAD-03 not done**: the ranking rows are a fixed `grid-cols-12` layout with no responsive breakpoints anywhere except the header (`md:flex-row`). On a narrow viewport this will clip/overflow. `docs/game-design/ui/mobile-standard.md` requires 48x48px minimum touch targets and no hover-gated content (current rows use `group-hover:` for cosmetic shifts only, which is fine, but the column layout itself isn't mobile-safe).

**Revised scope for this plan**: not "build a leaderboard," but (a) add a "Your Standing" indicator using `getPlayerRank`, shown regardless of whether the player is in the visible top-N, and (b) make the ranking rows responsive below `sm`/`md` breakpoints.

## Plan

1. Add `useMyRank()` hook in `frontend/src/hooks/useFarm.ts` (same file/pattern as `useLeaderboard`) calling `backendActor.getPlayerRank(identity.getPrincipal())`, gated on `!!backendActor && isAuthenticated`.
2. In `RankingsPanel.tsx`, render a small "Your Standing" stat card above the table using `useMyRank()` + the player's own prestige (already available via existing `playerStats`/leaderboard entry lookup) — shows rank even if outside the visible cached list ("Unranked — keep growing" fallback if `null`).
3. Add responsive classes to the row grid: stack identity/prestige/seasons/revenue vertically below `sm`, keep the 12-col grid at `sm:` and up. Reuse existing Tailwind tokens already used elsewhere in the file (`amber-500`, `mechanical-hull`) — no new design tokens.
4. No backend changes — `getGlobalLeaderboard`/`getPlayerRank` already exist and are already candid-bound.

## Success Criteria

1. Player sees their own rank and prestige even when not present in the top-N cached leaderboard.
2. Ranking list is usable (no clipped/overflowing columns, tap targets ≥48px) at a 375px-wide viewport.
3. `npm run build` and existing Vitest suite still pass — no regression to `useFarm.ts`/`RankingsPanel.tsx` consumers.

## Out of Scope for this plan

- Any backend change (both query functions already exist).
- Redesigning the visual style (Neo-Steampunk aesthetic, existing color tokens, animations kept as-is).
