# Plan 09-01: Implement sketch 001 winner (UX-06) — surgical canopy replacement

**Phase:** 9 — UX/UI Deep Overhaul
**Requirements:** UX-06 (this plan). UX-07 (port WorkerNPC to path network) and UX-08 (machines) deferred to a follow-up plan — see Out of Scope.

## Discuss (findings that changed scope)

Read the full `ImperialOrchard.tsx` (1366 lines) before touching anything. It is far more built than the earlier UX audit implied:

- **Multi-parcel isometric layout already exists**: `projectToIso(row, col, sectorIdx)` places each parcel as its own 5×5-tile "sector," sectors laid out side by side with visual bridges between them (`sectorsCount = displayParcels.length`).
- **Tree density math already exists and roughly matches the design-notes proposal**: `maxTrees = parcelSize * 400` (400 trees/ha), `visualTreesCount = sqrt(plantedTrees/maxTrees) * 25` capped at 25 slots per sector, placed via a deterministic seeded shuffle (`getDeterministicSlots`). This is a real, working density abstraction — not a stub.
- **Worker system already exists**: `WorkerNPC` with Manhattan-grid movement, bridge-crossing between sectors, phase-aware targets (walks to tree slots during Harvest/Awakening/Bloom, shelters during Dormancy), `hasHelper`-gated second NPC. Real state machine, not decoration.
- **What's actually bad** (matches the original complaint): `MechanicalTree`'s `renderCrown()` — a `filter: blur(3.5px)` div stack faking leaf clusters — and the recursive `Branch` DOM component for structural branches. This is the only piece being replaced.
- Game phases are `Dormancy/Awakening/Bloom/Harvest/Decay` (5), sketch 001 has 4 season buckets (`spring/summer/autumn/winter`). Mapping: Dormancy→winter, Awakening→spring, Bloom→spring, Harvest→summer, Decay→autumn. Awakening and Bloom collapsing to one bucket loses a distinction the old code had (small buds vs. peak blossom) — accepted as a reasonable simplification, noted here rather than silently dropped.

**Revised scope**: not a rewrite of `ImperialOrchard.tsx` — a surgical replacement of `MechanicalTree`'s internal rendering (DOM blur/branches → a small per-tree `<canvas>` running sketch 001's Variant A "Geometric Brass" draw functions) and a lighter seasonal-ground-decor addition to `GroundParcel`. Everything else (projection math, worker system, tree slot calculation, click/selection state, radial action menu, storage silo, zoom controls) is untouched.

## Plan

1. **Port Geometric Brass tree drawing** from `.planning/sketches/001-orchard-isometric-trees/index.html`'s final `drawTreeA`/`drawTrunk`/`drawGearIcon`/`drawCherry`/`drawBlossom`/`leafRadialFill`/`darkenHex`/`SEASON_CONFIG` into a new module (`frontend/src/components/farm/geometricBrassTree.ts`), adapted to draw relative to a single tree's own small canvas origin instead of an isometric grid offset.
2. **Replace `MechanicalTree`'s internals**: keep the outer positioned wrapper, shadow, and brass base ring exactly as-is; replace `renderCrown()` + the DOM `Branch` trunk/branches with one `<canvas>` (sized to the tree's existing 80×90 bounding box), drawn once per `(seed, phase, isHarvested)` change via `useEffect`+`useRef`. Map `styles.phase` to the sketch's season buckets per the table above.
3. **Winter canopy**: per the already-locked decision (sketch revision 7), winter draws the same faceted-canopy structure as autumn, recolored to the snow palette — not bare branches. Remove the old `isWinter` bare-branch special case entirely (the ported code naturally handles this since `SEASON_CONFIG.winter` already has real facets).
4. **Ground decor**: add a lightweight seasonal ground-decor canvas to `GroundParcel` (grass tufts/flowers for spring, drier tufts for summer, fallen leaves for autumn, snow patches for winter), reusing the sketch's `drawGroundDecor`/`drawGrassTuft`/`GRASS_SHADES`/`LEAF_SHADES` logic, clipped to the existing diamond tile shape and scaled to this component's `TILE_W=96`/`TILE_H=48` (not the sketch's 140×78).
5. **Not touched in this plan**: `WorkerNPC`, bridges, perimeter border, zoom controls, radial action menu, storage silo overlay, `SeasonalVFX`. Path lanes and the outer buildable-zone border from the sketch are also deferred — this component's existing bridge/perimeter visuals already serve an equivalent role at this scale; revisit only if a later plan decides it's needed.

## Success Criteria

1. Trees render via Canvas 2D procedural drawing (Geometric Brass), not CSS-blur divs.
2. Winter trees show a full snow-colored canopy, not bare branches.
3. Tree density/slot logic, worker movement, click-to-select, and the radial action menu all still work identically to before (no regression).
4. `npm run build` passes clean.
